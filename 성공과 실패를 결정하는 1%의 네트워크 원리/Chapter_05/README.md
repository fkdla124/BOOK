# 방화벽
* 주로 사용되는 방화벽은 패킷 필터링형 방화벽이다.
* MAC, TCP/IP 헤더쪽 정보를 가지고 필터링한다.
* TCP 3-way handshake 
ACK, SYN 제어비트를 적절히 활용하여 서버쪽에서 나가는 방향, 들어오는 방향 등을 적절히 필터링 할 수 있다.
* UDP
이 과정이 없기에 어느정도 감수하고 허용하거나 원천차단한다.
* 라우터
내장된 패킷필터링 기능으로도 방화벽으로 사용할 수는 있다. 하지만 메모리가 적어서 로그를 남기거나 하는 데에는 애로사항이 생긴다. 그럴 때는 방화벽용으로 따로 나오는 하드웨어를 사용하는 것이 좋다.

# 부하분산
* 서버에 들어오는 요청을 분산한다.

### DNS 서버의 라운드로빈
* 서버 기기를 여러대로 나누고 DNS서버가 클라이언트의 요청마다 IP를 라운드 로빈 형태로 나누어준다.
* 이전 페이지와 다음 페이지의 데이터가 연관된다면 접속한 아이피가 달라지기에 데이터가 유지되지 않을 수 있다.

### 로드밸런서 장치
* DNS서버가 주는 IP를 로드밸런서 장치IP로 돌린다.
* 로드밸런서 장치가 서버의 IP를 클라이언트의 요청마다 분배해준다.
* 현재 서버의 부하에따라, 이전 페이지와의 데이터 연관성에 따라 분배한다.
* 정기적으로 서버의 CPU, RAM 사용량 정보를 읽어오거나, 테스트패킷을 보내 응답시간을 테스트한다.
* 또는 애초에 서버마다 감당가능한 요청을 미리 계산해 그만큼만 분배하도록 설계한다. (이게 좋다고함)
* 이전 페이지와의 데이터 연관성은 HTTP헤더에 추가하거나, 데이터 자체에 구분할 수 있는 정보를 추가해서 판단한다.

### 캐시서버(프록시)
* 이미 요청한 적 있는 데이터를 보관해두고, 재요청시 캐시서버에서 준다. 서버의 부하를 줄이고 속도를 높인다.
* HTTP 헤더에 Via 필드가 생겨 캐시서버를 경유한 사실을 알 수 있다.
* 서버측에 두는방법: 서버측에서 관리할 수 있다. 네트워크측 트레픽은 줄지않는다. (리버스 프록시)
* 클라측에 두는방법: 서버측에서 관리할 수 없다. 네트워크측 트레픽이 줄어든다. (포워드 프록시)
* ISP POP에 두는방법: 서버측에서 관리할 수 있으며 네트워크측 트레픽도 줄어든다.

# CDSP 콘텐츠배포서비스
* 위 캐시서버를 ISP POP에 두려면 수많은 POP에 모두 캐시사버를 설치해야한다.
* 개인이 하기 힘든 일이기에 이걸 하는 업체가 존재한다. 이를 CDSP라고 부른다.

### DNS서버의 가까운 캐시서버 찾기
* DNS서버가 캐시서버들의 라우팅테이블 정보를 모두 갖고있는다.
* DNS서버에 요청이 들어오면 라우팅테이블 정보를 바탕으로 클라측과 가장 가까운 캐시서버를 판단하여 그 캐시서버의 IP를 준다.

### 리다이렉트 서버를 두기
* 리다이렉트 서버가 캐시서버들의 라우팅테이블 정보를 모두 갖고있는다.
* DNS서버에 요청이 들어오면 리다이렉트 서버의 IP를 돌려주고, 리다이렉트서버가 HTTP 헤더필드에 가까운 캐시서버의 IP가 담긴 Location 필드를 부가한 후 응답해준다. 클라는 Location 태그를 보고 거기로 다시요청한다.
