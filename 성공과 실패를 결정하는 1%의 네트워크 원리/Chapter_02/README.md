# 백지 인출해보기

2장은 OS 프로토콜 스택 내부에서 TCP, IP, 이더넷 헤더를 붙여 최종 패킷을 작성하고, LAN 어뎁터에서 디지털 데이터인 패킷이 케이블을 타고가는 전기신호로 바뀌어 케이블로 나가기 직전까지를 다룬다.

# 소켓을 만든다. (socket)
어플리케이션 코드에서 소켓 api를 통해 socket() 함수를 호출하면 소켓을 만들게 된다. 앞으로 네트워크 통신을 하며 필요한 여러 제어정보들을 저장할 메모리를 할당하며(아마 커널오브젝트?) 거기에 초기 값들을 세팅하며 초기화해준다.

# 만든 소켓으로 접속한다. (connect)
dns 리졸버를 통해 ip주소를 얻고, 그 ip주소와 포트번호(소켓 구분용)를 connect() 함수에 인자로주며 상대와 connect 한다. 이 동작의 실체는 데이터가 없는 여러 프로토콜 스택의 헤더만 존재하는 제어패킷을 주고받으며, 서로가 통신하는 데에 필요한 정보를 주고받는다. (SYN 비트 1,시퀀스번호 초기값, 윈도우사이즈) 서로 제어패킷을 송신하고 ACK를 수신하는 과정을 한 번씩 한다.

# 통신을 한다.
기존에는 송신 후 ACK를 기다리고 ACK가 오지않으면 재송신하는 구조이다. ACK를 기다리는 시간을 타임아웃시간이라고 부른다. 이는 최근에 통신하는데 걸린 지연시간을 기반으로 동적으로 늘어났다 줄어들었다 한다. 윈도우 사이즈 개념이 등장한다. 이로인해 ACK를 기다리지 않고도 수신측의 윈도우사이즈만큼 송신측에서 고려하여 데이터를 연속적으로 보낸다. 윈도우사이즈가 여유가 생길 때마다 여유 윈도우사이즈를 상대에게 송신하는 방법, 일정 주기마다 현재 윈도우사이즈와 ACK번호를 송신하는 방법이 적절하게 같이 쓰이며, OS 프로토콜스택에서 애플리케이션쪽으로 데이터가 이동하는 순간이 윈도우사이즈에 여유가 생기는 순간이다.

# 소켓을 말소한다.
통신이 끝나면 서버쪽이나 클라이언트쪽 어느쪽이든 어플리케이션 쪽에서 close()를 호출하고, OS 프로토콜스택 쪽에서 TCP 헤더쪽 제어비트에 FIN을 1로 설정하고 패킷을 보낸다. 이후 ACK로 응답을 받으며, 이를 양쪽에서 모두 수행한 후 몇분의 대기시간 이후 소켓을 말소한다. 대기시간이 있는 이유는 많은 이유가 있으며, 안정성을 위해서 인 것 같다. 예시로 소켓을 지우고 같은 포트번호에 바로 소켓을 만들었는데, 뒤늦게 FIN 비트가 켜진 패킷이 날아온다던지 하면 오동작 하게될 수 있다.

# TCP 헤더
1. TCP 프로토콜 스택쪽에서는 송신할 데이터를 일정 세그먼트로 나누어 그 앞에 TCP 헤더를 붙인다.
2. MTU : Maximum Transmission Unit (IP헤더 + TCP헤더 + Segment) 항상 MTU로 패킷을 꽉 채워서 보내면 통신 효율이 좋지만 응답성이 떨어질 수 있다. 그래서 응답성과 효율 사이에서 잘 조절한다.
   MSS : Maximum Segment Size (MTU - TCP/IP헤더크기)
3. 시퀀스번호 : 다음 데이터 세그먼트의 시작바이트다.
4. ACK 번호 : 지금까지 처리한 세그먼트 바이트 + 1 (다음에 받을 시퀀스번호) 이를 비교하여 데이터가 잘 도착했나 확인할 수 있다.
5. 윈도우 사이즈 : 한 번에 쌓아둘 수 있는 패킷의 양 (바이트단위) 이를 connect 시점에 미리 받아두고 이 윈도우사이즈에 맞게 ack를 기다리지않고 바로바로 데이터를 송신한다.
6. 제어비트 : SYN, FIN, ACK 등 여러 상태값을 나타내는 플래그 영역이다.
7. 포트번호 : 수신측 소켓을 구분하기위한 번호
이외에 더 있지만 여기까지 기억이난다.

# IP 헤더 (MAC헤더 포함)
1. 송신, 수신측 IP주소
2. 패킷 ID : 패킷을 일정 조각으로 분리할 때 분리된 패킷을 식별하기 위해 필요.
3. 프래그먼트 오프셋 : 이 조각의 오프셋을 나타냄.
4. 프로토콜 번호 : TCP, UDP, ICMP 등 프로토콜 번호가 기록된다고 한다.
5. MAC헤더의 송신, 수신측 MAC주소이며 ARP 프로토콜로 IP주소를 통해 MAC주소를 알아낸다. ARP 프로토콜은 나와 이어진 장치 모두이게 이 IP 주인은 누구냐고 브로드캐스트해서 답을 얻는 방식이다. LAN 어뎁터의 MAC주소는 어뎁터 내부 ROM에 저장되며, 부팅 시에 이걸 읽어서 세팅한다. 또는 설정파일에서 읽게끔 세팅할 수도 있으며, 이 경우에 ROM은 무시된다.
6. MAC해더의 이더타입 : IP, ARP 등 프로토콜 타입이다.
이외에도 많으니 궁금하면 책을 참고하자.

# 이더넷 헤더
프리앰블 비트 + 스타트 딜리미터 : 이는 LAN 어뎁터쪽 신호를 받는 회로쪽에서 신호의 주파수를 동기화하기위해 필요하다고 한다. 약간 예열작업 느낌? 잘은 모르겠다.
FCS : Frame Check Sequence. 예전에는 패킷을 프레임이라고 불렀다고 한다. FCS는 패킷 꼬리에 붙고 헤더부터 어떠한 연산을 거쳐서 만들어진다. 이걸 비교해서 패킷의 손상을 검출하고 손상이 있다면 패킷을 폐기한다.

# UDP
UDP는 데이터의 어느부분이 잘 도착했는지를 세세하게 따지지 않는다. 그냥 통으로 보내고 일부가 손상되었거나 아예 보내지지 않았다면 다시 통으로 보낸다. TCP는 세세하게 어디까지 갔고 어느부분이 이상한지 따지고, 이를위해 윈도우사이즈, ACK, 시퀀스번호 등등이 필요하지만 UDP는 이런게 필요가없다. 그래서 TCP에서 연결쪽이 UDP에서는 필요가없다. UDP의 사용 예시는 데이터가 짧아서 한 개의 패킷 안에 쏙 담을 수 있어서 전부를 다시보내는 특성이 손해가 없을 때 쓰이거나, 영상처럼 연속적으로 데이터를 받아야하는데, 일부가 잘못가는 것이 크게 상관이 없거나, 다시 보내봤자 쓸모가 없는 그런 경우에 사용된다고 한다. 음악이나 영상은 데이터가 손상되어도 잠깐 지직할 뿐이며 다시보내도 이미 쓸모가 없어진 시점일 것이다.

# 허브
리피터 허브 : 송신한 신호를 연결된 다른 모든 장치에 뿌린다. 신호를 그대로 뿌리는게 오리지널이지만 요즘은 신호를 증폭시켜서 또렷하게 만들어준다고 한다. 반이중모드로 하나의 신호만 다룰 수 있어서 여러 신호가 감지되면 재밍신호로 이를 알리고 장치들에게 대기시간을 랜덤하게 부여해서 신호를 하나씩 받는다
스위치 허브 : 송신한 신호를 LAN 어뎁터와 유사한 하드웨어들로 데이터로 변환한 뒤, MAC주소를 비교하여 알맞은 곳으로 다시 신호로 변환하여 쏴준다. 내부에 스위치 회로를 활용하여 스위치 허브란 말이 붙었고, 전이중모드가 가능하다 (목적지로 알맞게 보내줌)
