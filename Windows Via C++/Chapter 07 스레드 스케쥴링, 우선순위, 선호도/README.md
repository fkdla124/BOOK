# 윈도우는 선점형 멀티쓰레드 기반 시스템
* 0 ~ 31 사이의 우선순위를 기반으로 쓰레드들을 스케쥴링 한다
* 우선순위가 높은 쓰레드가 낮은 쓰레드를 선점할 수 있다

### 기아상태
* 우선순위가 높은 쓰레드가 계속 선점하여 우선순위가 낮은 쓰레드가 절대 실행되지 않는 상태

### 쓰레드 정지와 리썸
* SuspendThread()
* ResumeThread()
* Sleep()
* 위 함수들로 쓰레드나 프로세스를 정지하거나 다시 스케쥴링 할 수 있다
* 커널오브젝트의 정지카운트를 증감하는 방식이며, 0이되면 수행가능한 상태다
* 쓰레드가 어떤 일을 하고있던, 심지어 락을 잡고 뭔가를 하던말던 지금당장 Suspend 시킨다. 따라서 데드락 발생 가능성이 있다
* Sleep(0)은 0초 쉬는거라 지금당장 퀀텀을 포기하는 효과가 있다

### 다른 쓰레드로 전환
* SwitchToThread()
* Sleep(0)과 다른점은 일정시간 cpu시간을 할당받지 못하고있는 우선순위가 낮은 쓰레드들이 감지되면 그 쓰레드들을 1퀀텀 스케쥴링 해준다. 이후는 이전과 동일하게 작동한다

### 하이퍼쓰레딩
* cpu 내부 캐시메모리는 공유하되 컨텍스트는 두 개를 만들어 두 개의 쓰레드가 동시에 한 코어에 올라갈 수 있는 기술이다
* 두 쓰레드중 한 쓰레드가 분기예측 실패, 캐시미스, 인스트럭션 결과대기 등으로 인해 실행되지 못할 때 나머지 한 쓰레드가 실행된다
* 캐시메모리는 공유하기때문에 완전한 물리적 개별 cpu는 아니다

### 스레드 cpu시간
* GetThreadTimes()
* 일반적인 타이머함수들로 코드의 수행시간 측정을 하면 인터럽트나 다른스레드의 컨텍스트스위칭으로 인해 수행하지 못한 시간도 포함된다
* 제대로된 스레드의 cpu시간을 구하기위해서는 이 함수를 사용한다
* 스레드 생성, 삭제 타임스탬프와, 커널타임 유저타임을 제공한다
* 커널타임 = 커널코드 수행시간, 유저타임 = 유저코드 수행시간

# CONTEXT 구조체
* GetThreadContext() 로 유저컨텍스트를 얻을 수 있으며, 쓰레드를 Suspend 시키고 얻어야 한다
* 컨텍스트 스위칭 시에 활용되는 스레드의 컨텍스트 정보를 담고있는 구조체
* ip, sp, 여러 flag, 함수 반환주소, 정수레지스터, 부동소수점레지스터, 세그먼트레지스터, 디버그레지스터 등이 있다
* 커널모드에서 쓰레드가 Suspend 되어도 커널코드를 끝까지 수행하며 이는 유저컨텍스트와는 상관없기에 신경쓰지 않아도 된다고한다

# 쓰레드 우선순위
* 프로세스의 우선순위인 우선순위클래스가 존재하고 쓰레드 우선순위가 존재한다.
* 두가지 우선순위를 적절히 결합하여 사용하고 이 표는 책과 msdn에 있다.
* 0 ~ 31 까지 존재한다.
* 0은 제로페이지쓰레드 가 유일하다.
* 1 ~ 15 동적 우선순위 범위 16 ~ 31 실시간 우선순위 범위이다.
* 실시간 우선순위 범위는 주로 OS가 사용하는 영역이다.
* 동적 우선순위 범위의 쓰레드들은 우선순위 부스트를 받을 수 있다. 예시로 키보드 입력 메시지가 들어오면 디바이스 드라이버가 우선순위 +2를 요청하고 CPU 1퀀텀마다 -1씩 되는 구조다. 그리고 절대 15를 넘지 않는다.
* 윈도우는 3초에서 4초동안 수행되지 못한 스케쥴링된 쓰레드가 있다면 우선순위를 15로 만들어 2퀀텀을 수행시켜준다.

### 포그라운드 프로세스
* 사용자가 작업중인 화면 최전방 프로세스다.
* 윈도우는 포그라운드 프로세스가 우선순위 클래스 보통인 경우에 한해 cpu 퀀텀시간을 조금 더 길게하여 응답성을 개선한다

### 백그라운드 프로세스
* 포그라운드보다 뒤에있거나 아예 백그라운드에서 도는 프로세스다.

# 선호도
* 쓰레드들은 같은 cpu 코어에서 실행되면 캐시를 활용하여 속도가 더 빠를 수 있다.
* SetThreadAffinityMask()
* 위 함수로 OS에게 쓰레드 선호도를 위한 힌트를 줄 수 있다.
* 설정하면 최대한 그 코어로 가지만 100% 확정은 아니다.
