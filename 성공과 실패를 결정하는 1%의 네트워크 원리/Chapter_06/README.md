# 6장 주요내용
* 최종적으로 서버에서 클라이언트의 패킷을 받은 시점을 다룬다.

# 서버의 소켓
* 서버는 소켓을 미리 만들어두고 대기한다. 웹이라면 80포트.

### socket()
* 소켓을 관리하기 위한 내부 디스크립터를 생성한다.

### bind()
* 생성한 디스크립터를 사용해 특정 포트에 소켓을 바인딩한다.

### listen()
* 소켓을 접속대기상태로 만들어준다.

### accept()
* 함수 내부에서 os 프로토콜스택이 데이터를 건내줄 때까지 블록된 상태로 대기한다.

# 클라이언트마다 커넥션을 쓰레드 단위로 관리한다.
* 서버 프로그램이 데이터를 수신하면 만들어둔 소켓을 복제하여 그것을 가지고 새로운 쓰레드를 생성한다.
* 소켓 복제는 서버측에서 같은 포트로 이루어지고. 여러 커넥션을 구별하기위해 클라이언트, 서버측 ip와 포트 총 4가지를 가지고 구분한다.
* 클라이언트의 요청마다 새로운 쓰레드 하나가 생성되어 요청을 처리하고 복제한 소켓을 지우고 쓰레드도 지워진다.
* 더 빠른 응답을 위해 쓰레드풀을 이용할 수 있다
* 최종적으로 최초로만든 접속대기 소켓은 계속 접속대기만 하는 꼴이다.

# 데이터 수신 과정
* 앞에서배운 패킷을 만드는 과정의 역순이라고 볼 수 있다.

### LAN 어뎁터
* 신호가 케이블을타고 LAN 어뎁터의 PHY로 들어온다.
* 이더넷 헤더부분에 프리앰블 비트와 스타트 딜리미터로 신호를 제대로 받을 수 있게 클록을 동기화한다.
* 신호를 디지털 데이터로 변경하여 패킷에 FCS 부분을 이용하여 CRC-32 방식으로 패킷이 손상되었는지 체크하고. 손상되었다면 폐기한다.
* 패킷이 정상적이라면, MAC헤더에 MAC주소를 확인하여 나에게 온 것이 맞는지 확인하고 맞다면 버퍼에 보관한다.
* 패킷을 버퍼에 보관하면 인터럽트를 통해 OS의 인터럽트 핸들러를 호출한다.
* 네트워크 드라이버 코드가 작동하며 OS 프로토콜스택쪽으로 패킷을 건네주며 호출한다.

### IP
* IP헤더에 IP정보를 확인하여 자신에게 온 것인지 확인한다.
* 내 것이 아니고, 라우팅 기능이 활성화 되어있다면 알맞은 목적지로 라우팅하여 재송신한다.
* 패킷의 프래그먼트 여부를 IP헤더를 통해 확인하여 분리되어있다면 합친다.
* IP헤더에 프로토콜 정보를 확인하여 TCP라면 TCP쪽으로, UDP라면 UDP쪽으로 보낸다.

### TCP
* TCP 헤더에 여러 제어비트 SYN, ACK, FIN 등을 확인하여 올바르게 작동했는지 검사한다. (시퀀스번호 검사)
* 나누었던 세그먼트를 다시 합쳐서 원래의 데이터로 만든다.
* 애플리케이션에게 데이터를 넘겨준다.

* 접속패킷
1. SYN 비트 확인
2. 수신처 포트 확인
3. 해당하는 접속 대기 소켓 복제
4. 송신처의 IP주소와 포트번호 기록

* 데이터패킷
1. 송신, 수신측의 IP, 포트로 해당하는 소켓 구별
2. 데이터 세그먼트를 조립하여 수신버퍼에 보관
3. 클라이언트에게 ACK 송신

* 접속끊기패킷
1. FIN 비트 확인
2. ACK 송신
3. 안정성을 위해 몇분정도 대기후 소켓 제거

### 애플리케이션
* 넘겨받은 데이터를 원하는 대로 처리한다. 브라우저의 http 리스폰스라면 페이지를 띄워줄 것이다.
