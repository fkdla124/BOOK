# 이 장에서 학습한 내용 백지 인출해보기.
1. 브라우저 URL 입력 -> 브라우저에서 Socket 라이브러리의 DNS 리졸버를 이용하여 도메인의 IP주소 획득. -> OS 프로토콜 스택에 IP주소를 전달하며 HTTP 리퀘스트 메시지 송신을 의뢰.
2. IP주소 = 서브넷 번호 + 장치 번호.  서브넷마스크로 어디까지가 서브넷 번호인지 표시해줌. <br>
   장치번호쪽 비트가 모두 0이면 그 서브넷 자체를 뜻함(AI가 허브 그 자체를 뜻하는 것은 아니라고 한다). 비트가 모두 1이면 그 서브넷의 모든 장치를 브로드캐스트 한다는 의미. 
3. 클라이언트 <-> 허브 <-> 라우터 <-> 허브 <-> 서버 구조. 허브가 관리하는 장치들의 묶음을 허브를 포함하여 서브넷이라 부름.
4. 네트워크는 데이터가 여러 서브넷의 허브, 라우터를 타고다니며 최종 목적지 장치까지 이동.
5. DNS 리졸버는 가장 가까운 DNS서버에 IP주소를 요청하고, 가장 가까운 DNS서버는 루트 도메인서버부터 차근차근 탐색하며 IP주소를 찾아감. <br>
   ex) www.example.co.kr. 주소에서 마지막 .이 루트도메인(주로 생략) -> kr도메인서버 -> co도메인서버 -> example도메인서버 -> www도메인서버 <br>
   도메인서버는 캐시가 존재하여 이미 찾았던 IP주소는 일정 유효시간을 가지고 캐시에 올라가있음. 만약 캐시에 있다면 여러 도메인서버를 거치지 않아도 바로 찾을 수 있음. <br>
6. HTTP 메시지의 리퀘스트 리스폰스 형식에 대해 다룸. GET, POST, PUT, DELETE 등의 메소드 들이 있음. <br>
   리퀘스트 <br>
   [메소드] [URI] [HTTP버전] <br>
   [필드명][필드값] <br>
   <br>
   [메시지 본문] <br>
   <br>
   리스폰스 <br>
   [HTTP 버전] [스테이터스 넘버] [응답 문자열] <br>
   [필드명][필드값]<br>
   <br>
   [메시지 본문]<br>
  <br>
7. www.example.co.kr -> 이것은 자동으로 마지막에 /를 붙이는 것으로 치환된다.  <br>
   www.example.co.kr/ -> 이것은 루트 디렉토리의 index.html을 GET 메소드로 요청한다. (설정에서 바꿀 수 있는 걸로 기억함)<br>
   www.example.co.kr/abcd -> 이것은 abcd파일이 있으면 파일이고 없으면 abcd 디렉토리로 인식한다.<br>

8. IP주소는 어떤 서브넷의 어떤 장치인지를 알려준다.
   그 장치의 어떤 소켓을 의미하는 지는 포트번호가 그 역할이다.
